# 从“会动”到“可信”：VLA 权重可靠性评测工作介绍报告

## 报告目的

这份报告面向此前没有接触过 VLA、机器人 benchmark 或模型评测的读者，说明三个问题：

1. VLA 是什么，为什么机器人需要这种模型；
2. benchmark 通过什么原理、指标和流程量化一个模型权重的可靠性；
3. 我们已经如何评测 OpenPI 的 `pi05_libero` 权重，得到了什么结论，又有哪些结论不能由本次评测直接推出。

本报告尽量避免算法术语。可以先记住一句话：

> **我们所做的工作，相当于给一个“会看、会理解指令、会动手”的机器人模型安排标准考试、压力考试和完整监考，并把每一次操作的结果、录像和运行证据保存下来，以判断这份权重在规定范围内究竟有多可靠。**

---

## 一、VLA 是什么

### 1. 一个“会看、会理解指令、会动手”的机器人控制模型

VLA 是 **Vision-Language-Action** 的缩写：

- **Vision（视觉）**：读取机器人摄像头拍到的画面；
- **Language（语言）**：理解人给出的任务指令，例如“把黑色碗放到盘子上”；
- **Action（动作）**：输出机器人下一段应该执行的控制动作。

传统工业机器人更像按照固定脚本运动的机器：物体、位置和动作流程往往必须事先精确规定。VLA 则更像一个通过大量数据训练出来的“机器人脑子”：它看到当前场景、读懂指令，然后自己判断接下来如何移动。

`π0.5` 是 Physical Intelligence 提出的一类 VLA 模型。其研究目标之一，是让模型能够把从不同机器人、任务、视觉和语言数据中学到的知识迁移到新环境和新物体上。[π0.5 论文](https://arxiv.org/abs/2504.16054)将这种目标称为开放世界泛化。

### 2. VLA 不是一次性给出完整答案，而是不断闭环决策

机器人操作是一个连续过程。以“把碗放到盘子上”为例，模型不能只在开始时看一眼场景，然后盲目执行到底。实际过程更接近：

```text
读取当前画面与机器人状态
          ↓
结合语言指令生成一小段动作
          ↓
机器人执行动作，场景发生变化
          ↓
再次观察，再次生成动作
          ↓
直到任务成功，或达到允许的最大步数
```

这种“观察—决策—执行—再观察”的循环叫作**闭环控制**。它也是 benchmark 真正要测试的内容：模型不仅要认出物体和理解句子，还必须把理解转化为一连串正确动作，并根据动作后的新画面继续调整。

### 3. “模型”“权重”和“checkpoint”分别是什么

可以用“学生、知识和考试存档”来理解：

| 概念 | 通俗解释 |
|---|---|
| 模型结构 | 学生的大脑结构，规定信息如何被处理 |
| 权重（weights） | 学生训练后真正记住的知识与行为规律 |
| checkpoint | 某个训练时刻保存下来的完整存档，通常包括权重及配套配置 |
| norm stats | 输入和动作数据的“单位换算表”，使训练和推理使用一致尺度 |
| assets | 环境、任务或模型运行所依赖的配套资源 |

同一种模型结构可以有多份不同权重。权重不同，机器人表现可能完全不同。因此，我们评测的不是一个抽象的“π0.5 名字”，而是一个可精确识别、具有固定参数文件和哈希值的具体 checkpoint。

## 二、benchmark 是什么，为什么不能只看演示视频

### 1. Benchmark 是统一试卷和统一考场

Benchmark 可以理解为一套标准化考试：它规定考什么、场景如何初始化、任务成功如何判定、最多允许执行多少步、每道题重复多少次，以及最终如何计分。

[LIBERO](https://arxiv.org/abs/2306.03310)最初是一套用于机器人操作与知识迁移研究的标准环境。它在模拟器中提供不同物体、空间关系、目标和长时序任务，让研究者能在相同条件下比较模型。

模拟环境的价值不是“证明现实世界一定安全”，而是先建立一个可重复的实验室：同一道题可以重复运行，可以控制初始状态，可以自动判断成功，也可以对不同权重做公平对照。

### 2. 为什么成功演示不能代表可靠

一段成功录像只能证明“模型至少成功过一次”，不能回答下列问题：

- 这次成功是否只是运气好？
- 摄像机稍微换一个角度还会成功吗？
- 物体位置变化后是否仍然有效？
- 语言换一种说法，模型是否还能理解？
- 十次、五十次或上千次运行中，失败比例是多少？
- 失败是模型不会做，还是服务器、渲染或连接坏了？
- 是否有困难任务被漏跑，却仍然生成了一个看似漂亮的平均分？

因此，可靠性评测必须同时具备**足够多的样本、明确的任务覆盖、可解释的分组指标和完整证据链**。

### 3. Benchmark 像驾照考试，但比驾照考试记录得更多

可以把一次 VLA benchmark 想成一次机器人驾照考试：

- benchmark 是规定路线和评分规则；
- checkpoint 是参加考试的驾驶员；
- episode 是一次上车考试；
- success/failure 是这一趟是否完成；
- 录像是行车记录仪；
- JSONL 是逐次考试成绩单；
- server/client 日志是车辆与考场设备日志；
- Git commit、配置和哈希是试卷版本、车辆编号和封条编号；
- 最终审计是确认没有漏考、重考冒充、设备故障算作驾驶失败或成绩被改写。

## 三、一次 VLA 评测究竟怎样运行

我们的评测以一个 episode 为最小单位。一次完整 episode 包括：

1. **初始化场景**：加载指定任务、物体位置和机器人初始状态；
2. **发送任务指令**：例如“把奶放进篮子”；
3. **获取观察**：读取摄像头图像和机器人状态；
4. **模型推理**：把观察和语言发送给固定 checkpoint；
5. **动作检查**：确认返回动作数量和维度正确，且没有 NaN/Inf；
6. **执行一小段动作**：本次协议每次重规划前执行 5 步动作；
7. **重新观察和规划**：不断循环，直到成功或达到最大步数；
8. **写入证据**：保存成功/失败、动作步数、耗时、错误分类、日志和录像。

本次固定协议包括：

- 策略输入图像：224×224；
- 每次重规划执行：5 步动作；
- 每步动作：7 维有限数值向量；
- 环境 seed：7；
- 渲染后端：EGL；
- 初始等待：10 步；
- 最大动作步数：Spatial 220、Object 280、Goal 300、LIBERO-10 520。

固定这些参数的原因，是确保各次考试的规则一致。否则，两个权重即使面对同一道任务，也可能因为图像尺寸、动作频率或最长考试时间不同而无法公平比较。

## 四、“权重可靠性”不是一个数字，而是一个多维画像

日常语境中的“可靠”容易被理解成“任何时候都不会失败”。对 VLA 而言，这种结论几乎不可能由单一 benchmark 得出。

本报告中的可靠性，是指：

> **在固定 checkpoint、固定评测协议和明确任务范围内，模型完成任务的能力、面对变化时的稳定程度，以及这些结果本身是否完整、可复核。**

我们把它拆成六个维度：

| 可靠性维度 | 要回答的问题 | 主要量化方式 |
|---|---|---|
| 基础任务能力 | 标准任务是否会做？ | 原始 LIBERO 成功率、各 suite 成功率 |
| 泛化与鲁棒性 | 环境变化后是否仍会做？ | Plus 变化类别/Pro 扰动成功率、难度曲线、最差分组 |
| 重复稳定性 | 同一类任务多次运行是否稳定？ | task/source 的多 trial 分布、零成功 source 数 |
| 运行可靠性 | 分数是否被系统故障污染？ | 连接、EGL、环境、checkpoint 等错误计数 |
| 覆盖完整性 | 是否所有计划题目都真正跑完？ | evaluated/planned、唯一 episode 数、缺失矩阵 |
| 证据可审计性 | 每个分数能否追溯和复核？ | JSONL、录像、日志、manifest、哈希、代码版本 |

因此，我们不把所有维度强行合并成一个“可靠性总分”。一个 90% 的平均成功率可能掩盖某类任务只有 20%；一个 100% 的小样本结果也可能远不如 95% 的大样本结果可信。正确做法是报告一个**可靠性画像**。

## 五、我们用哪些 benchmark 检查权重

### 1. 原始 LIBERO：检查标准任务能力

原始 LIBERO 是基础考试。本次使用四个 suite：

- `libero_spatial`：空间关系任务；
- `libero_object`：不同物体操作任务；
- `libero_goal`：不同操作目标；
- `libero_10`：更复杂的长时序任务集合。

完整矩阵是：

```text
4 个 suite × 每套 10 个任务 × 每任务 50 次 trial = 2000 episodes
```

它回答的是：“这份专门针对 LIBERO 微调的权重，在标准考试中是否达到预期？”

### 2. LIBERO-Plus：系统改变外观和初始条件

[LIBERO-Plus](https://github.com/sylvestf/LIBERO-plus)在原始任务基础上构造 10,030 个变体，按七类变化维度进行归类：

1. 物体布局；
2. 相机视角；
3. 机器人初始状态；
4. 语言指令改写；
5. 光照条件；
6. 背景纹理；
7. 传感器噪声。

每个变体本次评测一次，并带有难度分级。它更像压力测试，回答：“模型不是只会原始考题吗？画面、初始姿态或表达方式变化后还能不能做？”这些分类在本次数据结构中的正式字段名是 `category`，本报告统一称为“变化类别”。

### 3. LIBERO-Pro：检查模型是否只是记住训练分布

[LIBERO-Pro](https://github.com/Zxy-MLlab/LIBERO-PRO)强调在不同泛化扰动下评估 VLA，目标之一是减少仅靠记忆原始任务带来的虚高成绩。本次协议计划包含五类扰动：

- 物体替换；
- 位置交换；
- 语言语义改写；
- 任务替换；
- 环境扰动。

完整设计为：

```text
5 类扰动 × 4 个 suite × 10 个 source task × 50 次 trial
= 10,000 episodes
```

当前官方数据快照只提供了前四类的完整预生成单元，因此我们完成了 8000 episodes；缺失的四个环境扰动单元共 2000 episodes，明确标记为 **N/A**，没有当成失败。

## 六、用什么指标量化权重可靠性

### 1. 成功率：最直观，但不能单独使用

成功率定义为：

```text
成功率 = 成功完成的 episode 数 ÷ 有效策略 episode 总数
```

例如，官方权重在原始 LIBERO 上成功 1942 次、失败 58 次：

```text
1942 ÷ 2000 = 97.10%
```

这回答“总体有多少次完成了任务”，但不回答失败集中在哪。因此还必须按 suite、扰动、难度和 task/source 分层。

### 2. 覆盖率：先确认试卷真的做完了

覆盖率写成 `已评测数 / 协议计划数`。例如：

- Plus：10030/10030，矩阵完整；
- Pro：8000/10000，16 个可用单元完成，4 个环境单元 N/A。

如果不报告覆盖率，只给成功率，可能发生“只跑了容易题却声称高分”的问题。

### 3. Micro average 与 macro average

- **Micro average（微平均）**：把全部 episode 放在一起计算，样本多的分组权重更大；
- **Macro average（宏平均）**：先计算每个 suite 的成功率，再让各 suite 等权平均。

两者解决不同问题。微平均反映这批 episode 的总体通过率；宏平均避免某个大分组支配总分。本次 Plus 的微平均为 83.65%，四个 suite 的宏平均为 83.78%，两者接近，但仍需明确口径。

### 4. 分层成功率和最差分组

总平均可以掩盖局部崩溃。例如 Plus 总成功率为 83.65%，但相机视角变化类别只有 72.55%；在“相机视角 × LIBERO-10”这一更具体分组中，成功率进一步降至 55.13%。

因此，实际监测应同时查看：

- suite 成功率；
- Plus 变化类别/Pro 扰动类型成功率；
- 难度成功率；
- 扰动 × suite 热力图；
- 最差 task/source；
- 完全失败的 source 数量。

### 5. 置信区间：说明数字有多稳定

有限次数的考试总会有抽样波动。本报告使用 Wilson 95% 置信区间描述 episode 级成功率附近的合理范围。例如：

- 原始 LIBERO 97.10%，95% 区间约为 96.27%—97.75%；
- Plus 83.65%，约为 82.91%—84.36%；
- Pro 可用矩阵 58.79%，约为 57.70%—59.86%。

置信区间不是额外加分，也不表示跨环境、跨 seed 或真实机器人上的保证。它只描述当前样本和统计假设下的不确定性。

### 6. 失败分类：区分“考生不会”和“考场坏了”

我们把终态至少区分为：

- **策略成功**：任务完成；
- **普通策略失败**：模型在最大步数内没有完成；
- **环境异常**：模拟器或场景初始化问题；
- **连接异常**：client/server 通信失败；
- **checkpoint 不兼容**：权重或配套资源不满足协议；
- **N/A**：该协议或单元根本不可运行，不进入成功率分母。

本次全部普通失败都运行到了 episode 最大步数，且最终统计中的基础设施错误为 0。这意味着报告中的失败率没有把服务器、EGL、连接或初始化故障伪装成模型失败。

### 7. Task/source 分布：检查平均数是否掩盖“两极分化”

Pro 中每个 source 有 50 次 trial，因此可以观察同一 source 的稳定性。位置交换的 40 个 source 中有 20 个完全失败，任务替换有 19 个完全失败；对应 source 成功率中位数只有 1% 和 2%。

这说明 28.10% 或 24.30% 的平均值并不是“每道题都略微变差”，而是大量任务接近彻底失效，少数任务仍保持较高成功率。这种信息对风险判断比单一均值更重要。

### 8. 耗时和动作步数：监测评测成本与失败形态

动作步数可以区分“很快完成”和“持续尝试但最终超时”。耗时分位数可发现运行长尾。例如 Sensor Noise 只占 Plus 的 16.0%，却占 episode-duration 总和的 53.5%，其中位数为 36.6 秒、P90 为 177.1 秒。

这一指标主要帮助估算评测资源和定位慢任务，不应与成功率混为一谈。多 GPU 并行时，episode-duration 总和也不等于实际墙钟时间。

### 9. 完整性指标：证明分数可追溯

除了模型表现，我们还检查：

- episode ID 和 attempt ID 是否唯一；
- 计划矩阵是否全部覆盖；
- 每个策略终态是否只有一条权威记录；
- 录像数量是否与 episode 精确对应且文件非空；
- summary 是否能从 JSONL 重新计算得到；
- checkpoint 参数树、norm stats 和源数据是否有固定哈希；
- Git commit、环境依赖、GPU、启动参数和日志是否保存；
- 断点续跑是否会重复计数或静默漏跑。

这些检查不提高模型成功率，但提高“我们能否相信这个成功率”的证据质量。

## 七、我们具体做了什么

### 1. 建立三个对照协议

我们没有只运行官方权重，而是设计了三个相互解释的对照：

1. **官方 `pi05_libero` checkpoint**：检查官方 LIBERO 微调权重；
2. **`pi05_base` 参数 + 官方 LIBERO assets/norm stats**：判断仅配套正确归一化资源是否足够；
3. **`pi05_base` + 原生 assets**：若缺少 LIBERO norm stats，则记录协议不成立，不伪造零成功率。

这种设计能把“模型参数是否学会任务”和“输入尺度是否匹配”分开。

### 2. 分阶段降低工程风险

每种可运行协议均按以下顺序推进：

```text
权重与环境预检
    ↓
一次真实推理，检查动作形状和有限值
    ↓
Smoke：少量闭环 episode
    ↓
Full：完整任务矩阵
    ↓
分片合并、summary 重算和最终审计
```

预检和 smoke 的作用，是在投入数万次 episode 前发现 checkpoint、依赖、渲染或动作接口问题。

### 3. 隔离新 benchmark，避免污染原环境

LIBERO-Plus 与 LIBERO-Pro 使用独立仓库、独立 Python 3.8 环境和独立运行目录，没有替换原有 LIBERO 环境。策略服务只绑定到 `127.0.0.1`，通过本机 WebSocket 通信；启动器只终止自己创建的精确子进程，不扫描或杀死其他任务。

这降低了评测之间相互污染、依赖版本漂移和误终止无关进程的风险。

### 4. 在保持矩阵边界的前提下并行评测

Plus 的 10,030 episodes 按 suite 分片到多个独立 GPU/server。每个分片拥有不重叠的 episode ID、独立结果目录和独立录像，最终合并器要求四个 suite 的数量精确吻合，并拒绝重复 ID。

需要明确：环境 seed 固定为 7，但 OpenPI 策略随机流按 server 进程独立从 JAX key 0 开始。因此该结果在协议层面可复现，但不声称与“一个 server 连续跑完整个矩阵”位级等价。这一差异已写入协议和最终报告。

### 5. 保存完整证据并做最终独立审计

每个 episode 输出结构化 JSONL 和录像；每次运行保存 server/client 日志、环境清单、Git 状态、checkpoint 来源和哈希。最终审计不直接相信 summary，而是从 episode 记录重新展开矩阵并核对录像集合。

本地归档对超过 22,000 个普通文件保存了 SHA-256 清单，并保存 11,324 条符号链接定义，能够证明结果文件没有在归档后静默变化。每次新增报告后都会重新生成并核验最终清单。

| LIBERO | `pi05_base` + LIBERO stats/assets | 2000/2000 | 0 | 2000 | 0.00% | 0 | 完成，系统性策略失败 |
| LIBERO | `pi05_base` 原生 assets | 0/2000 | N/A | N/A | N/A | 0 | 缺 norm stats，不适用 |
| LIBERO-Plus | `pi05_libero` | 10030/10030 | 8390 | 1640 | 83.65% | 0 | 完成 |
| LIBERO-Pro | `pi05_libero` | 8000/10000 | 4703 | 3297 | 58.79% | 0 | 可用矩阵完成；2000 N/A |

不同 benchmark 的任务构成和分母不同，因此上表不是一张简单的“由高到低排行榜”。原始 LIBERO 是标准能力测试；Plus 和 Pro 是不同形式、不同强度的泛化压力测试。

### 2. 原始 LIBERO：标准任务能力强

官方 `pi05_libero` 权重达到 1942/2000，即 97.10%，超过本项目设置的 93.85% 验收线：

| Suite | 成功/总数 | 成功率 |
|---|---:|---:|
| Spatial | 493/500 | 98.60% |
| Object | 492/500 | 98.40% |
| Goal | 491/500 | 98.20% |
| LIBERO-10 | 466/500 | 93.20% |

58 次失败高度集中在少数任务。最困难的 “put both moka pots on the stove” 只有 30/50，单任务贡献 20 次失败。说明权重在标准任务上总体成熟，但长时序、多物体任务仍有明显长尾。

### 3. Base 对照：正确 norm stats 不等于会做任务

`pi05_base` 参数即使使用官方 LIBERO norm stats/assets，仍然是 0/2000，且全部 episode 均运行至最大步数后失败。这说明 Base 模型并非因为一个简单的数值单位问题才失败；LIBERO 任务能力主要来自任务微调后的权重。

### 4. Plus：外观变化较稳，几何和初态变化较弱

Plus 总体为 8390/10030，即 83.65%。

| 变化类别 | 成功率 | 解读 |
|---|---:|---|
| 光照条件 | 94.22% | 对光照变化较稳健 |
| 背景纹理 | 94.05% | 对表面和背景外观变化较稳健 |
| 传感器噪声 | 86.95% | 成功率尚可，但运行耗时长尾明显 |
| 语言指令 | 85.88% | 多数改写仍能执行 |
| 物体布局 | 84.98% | 有一定退化 |
| 机器人初始状态 | 73.16% | 明显短板 |
| 相机视角 | 72.55% | 明显短板 |

相机视角和机器人初始状态只占 31.4% 的 Plus episodes，却贡献 52.1% 的失败。难度 1—5 的成功率从 93.86% 单调下降到 61.50%；难度 4—5 占 39.6% 测试量，却贡献 68.8% 的失败。

### 5. Pro：语言理解不是主问题，关系重组才是

Pro 可用矩阵总体为 4703/8000，即 58.79%。

| 扰动 | 成功/总数 | 成功率 |
|---|---:|---:|
| 语言语义改写 | 1926/2000 | 96.30% |
| 物体替换 | 1729/2000 | 86.45% |
| 位置交换 | 562/2000 | 28.10% |
| 任务替换 | 486/2000 | 24.30% |

模型对“同一个意思换一种说法”非常稳健，对多数物体替换也仍然较强；但当物体位置关系或操作目标发生重组时，性能大幅下降。位置交换和任务替换贡献了 Pro 全部失败的 89.5%。

这说明当前权重更擅长识别和执行熟悉结构的任务，不足之处在于组合式几何和任务关系泛化。

## 九、如何用这些数据判断权重是否可靠

### 1. 当前权重的可靠性画像

| 维度 | 当前证据 | 判断 |
|---|---|---|
| 标准 LIBERO 能力 | 97.10%，通过 93.85% 验收线 | 强 |
| 外观变化鲁棒性 | 光照 94.22%，背景 94.05% | 强 |
| 语言表达鲁棒性 | Plus 语言 85.88%，Pro 语义 96.30% | 较强 |
| 物体替换能力 | Pro 86.45% | 较强但非完全稳定 |
| 相机视角鲁棒性 | Plus 72.55%，部分交叉分组更低 | 中等偏弱 |
| 机器人初始状态鲁棒性 | Plus 73.16% | 中等偏弱 |
| 位置关系重组 | Pro 28.10% | 弱 |
| 新任务目标重组 | Pro 24.30% | 弱 |
| 高难度任务 | Plus 难度 5 为 61.50% | 明显风险 |
| 评测系统可靠性 | 0 infra error，完整 ID/录像/哈希审计 | 强 |
| Pro 协议覆盖 | 8000/10000，环境扰动缺失 | 不完整，不能评价 env |

这份画像表明：**该权重在标准 LIBERO 和外观/语言变化下较可靠，但不能被概括为“已经具备全面泛化能力”。几何关系、初始状态、任务重组和高难度长时序任务仍是清晰的风险区。**

### 2. 为什么不能只宣布“83.65%可靠”

成功率不是可靠性的同义词。Plus 的 83.65% 是 10,030 个指定变体上的微平均；它没有告诉我们真实场景中会遇到哪些变体，也不表示每种变体都达到 83.65%。同理，Pro 的 58.79% 是四类可用扰动的平均，不包含环境扰动。

更合理的表述是：

> 在当前固定协议下，`pi05_libero` 在标准 LIBERO 上表现强；在 Plus 的外观与语言变化下总体保持较高成功率，但在视角和机器人初始状态上明显下降；在 Pro 的位置交换和任务替换上出现大面积 source 级失效。

## 十、今后如何持续监测每一份新权重

当产生新的 checkpoint 时，不应只跑一次总分，而应建立固定的版本化监测流程。

### 1. 第一层：身份与兼容性门禁

在运行任务前确认：

- checkpoint 文件数、总字节数和参数树哈希；
- 配置名称、norm stats 和 assets 来源；
- OpenPI、benchmark 和评测脚本版本；
- 动作输出至少满足步数、维度和有限值要求。

任何一项不匹配，都应停止并标记为 checkpoint/协议问题，而不是给出 0% 成功率。

### 2. 第二层：Smoke 闭环门禁

每个 suite/扰动至少完成一个真实闭环 episode，验证：

- 场景能够初始化；
- 图像能够渲染；
- 模型能够持续推理；
- 动作能够执行；
- 成功与失败录像能够落盘；
- client/server 连接可恢复。

### 3. 第三层：完整矩阵

只在 smoke 通过后进入 full，并强制要求：

- `evaluated == planned`，或所有缺失项均有明确 N/A 证据；
- episode/attempt ID 唯一；
- 无静默跳过；
- 基础设施异常单独计数，不进入策略分母；
- 断点续跑不重复计数。

### 4. 第四层：版本回归看板

建议每份新权重固定展示以下指标：

| 看板区域 | 必须展示的指标 |
|---|---|
| 标准能力 | 官方 LIBERO 总体、宏平均、四个 suite、最差 task |
| Plus 鲁棒性 | 七类变化、难度 1—5、类别 × suite 热力图、最差分组 |
| Pro 泛化 | 各扰动、扰动 × suite、source 中位数、零成功 source 数 |
| 系统质量 | infra errors、缺失/N/A、重复 ID、录像完整率 |
| 运行成本 | 动作步数、时长中位数/P90、长尾类别 |
| 复现信息 | 权重哈希、代码 commit、seed、RNG 作用域、环境清单 |

新版本不仅要看总体是否提高，还要检查：

- 是否出现某个弱分组显著退化；
- 是否用容易样本增多掩盖困难样本下降；
- 是否有 source 从可用变成完全失败；
- 是否出现新的基础设施错误；
- 是否改变了分母、任务版本或推理协议。

### 5. 建议的硬门禁与质量门禁

硬门禁应只针对证据与协议，不依赖模型水平：

- checkpoint 身份精确匹配；
- 任务矩阵完整或 N/A 有证据；
- 记录、终态和录像一一对应；
- 未知错误为 0；
- 基础设施错误不混入策略失败；
- 最终审计通过。

质量门禁则应由应用风险决定。例如本项目对官方 LIBERO 使用 93.85% 作为验收线；后续权重还可以设置“不得比当前基线退化超过指定百分点”“关键弱分组必须高于指定下限”等规则。阈值应在看结果前预先确定，避免根据结果临时移动标准。

## 十一、这次评测能证明什么，不能证明什么

### 能够支持的结论

- 具体的 `pi05_libero` checkpoint 在固定 LIBERO 协议中达到 97.10%；
- Base 参数即使搭配 LIBERO norm stats/assets，仍未获得 LIBERO 任务能力；
- 当前权重对外观和语言变化相对稳健；
- 相机视角、机器人初始状态、位置交换、任务替换和高难度任务是主要弱点；
- 当前归档中的成功率、分层指标和录像具有完整可审计证据；
- 最终统计没有把基础设施异常当作策略失败。

### 不能直接支持的结论

- 不能证明模型在真实机器人或所有现实环境中同样可靠；
- 不能证明模型具备碰撞安全、人机协作安全或异常恢复能力；
- 不能证明跨随机 seed 的性能方差，因为当前环境 seed 固定为 7；
- 不能评价 Pro 的环境扰动能力，因为 2000 个 `env` episodes 缺失；
- 不能把不同 benchmark 的总成功率当作同一难度下的直接排名；
- 不能把一次 benchmark 通过等同于模型未来版本或其他 checkpoint 也通过；
- 不能仅凭模拟器结果批准真实设备无人监管部署。

要进一步支持真实部署，还需要增加多 seed 重复、真实机器人试验、碰撞/力/速度等安全指标、异常恢复、延迟抖动、分布外检测以及人工接管机制。

## 十二、结论

我们现在完成的不是一次“跑分”，而是一套可追溯的 VLA 权重可靠性测量流程：

1. 用标准 LIBERO 判断模型是否具备基础任务能力；
2. 用 LIBERO-Plus 检查视觉、语言、初始状态和难度变化；
3. 用 LIBERO-Pro 检查物体、位置、语义和任务关系的泛化；
4. 用 Base 对照分离任务微调能力和数据归一化因素；
5. 用结构化记录、录像、日志、版本和哈希证明每个分数来源；
6. 用严格的失败分类防止考场故障被误算成模型能力问题。

最终结果显示，官方 `pi05_libero` 权重已经具备很强的标准 LIBERO 能力，并能较好应对外观和语言变化；但它对几何关系、机器人初始状态、任务重组和高难度长时序操作仍不够可靠。

因此，对这份权重最准确的评价不是“可靠”或“不可靠”二选一，而是：

> **在标准 LIBERO 和部分外观/语义变化范围内有较强可靠性；在位置关系、任务目标、初始状态和高难度组合变化下存在明确且量化可见的能力边界。**

这正是 benchmark 的价值：它不只是给模型一个分数，而是用标准化、可重复、可审计的数据告诉我们——模型在哪些条件下值得信任，在哪些条件下仍需要训练、保护和人工兜底。

## 附录 A：常用术语速查

| 术语 | 含义 |
|---|---|
| VLA | 接收视觉和语言、输出机器人动作的模型 |
| 权重 | 模型训练后学到的参数 |
| Checkpoint | 一份固定的模型存档及其配套配置 |
| Benchmark | 标准化任务、环境、规则和评分方法 |
| Episode | 从场景初始化到成功或终止的一次完整尝试 |
| Trial | 对同一任务的一次重复测试 |
| Suite | 一组性质相近的任务集合 |
| Source | Pro 中生成一组重复 trial 的具体任务来源 |
| Success rate | 成功次数除以有效策略尝试次数 |
| Micro average | 把所有 episode 合在一起计算的平均 |
| Macro average | 先按组计算，再让各组等权平均 |
| 95% CI | 当前样本下成功率统计不确定性的描述区间 |
| Infra error | 评测系统错误，不等同于模型策略失败 |
| N/A | 不适用或没有可运行数据，不进入成功率 |
| Seed | 控制部分随机过程的初始值 |
| Manifest | 记录环境、版本、来源和运行状态的证据文件 |
| SHA-256 | 用于识别文件内容是否发生变化的数字指纹 |
